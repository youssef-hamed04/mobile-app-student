# Data safety (Google Play) and App Privacy (App Store)

Traced from the code on 2026-09-29. If a release adds a data type, update this
file, the Play form, the App Store answers and `edu-dashboard/src/app/(public)/privacy`
in the same release.

## 1. Inventory — what the app actually collects

| Data | Required? | Source in code | Stored in | Why |
| --- | --- | --- | --- | --- |
| Full name | Required | `RegisterDto.fullName` → `users.fullName` | Neon | Account, watermark, support |
| Mobile phone number (Egyptian) | Required | `RegisterDto.phone` → `users.phone` (sign-in id) | Neon | Account, sign-in, support |
| Password | Required | argon2 hash only → `users.passwordHash` | Neon | Sign-in |
| Gender | Required | `RegisterDto.gender` → `users.gender` | Neon | Profile / course eligibility |
| University, faculty, department, academic year | Required | `RegisterDto` → `student_profiles` | Neon | Which courses are shown |
| Language | Required (default) | `users.locale` | Neon | UI / notifications language |
| Email | **Not collected from students** | `users.email` exists for staff only; not in RegisterDto or profile edit | — | — |
| Profile photo | Optional | `features/profile/avatar.ts` → presigned upload → `users.avatarUrl` | Cloudflare R2 | Profile |
| Support messages (incl. deletion requests) | Optional | `support_tickets`, `support_messages` | Neon | Customer support |
| Codes / recharge cards redeemed | Generated by use | `access_code_redemptions`, `wallet_transactions`, `recharge_revenue` | Neon | Access, wallet |
| Enrollments, part & library purchases, wallet ledger | Generated by use | `enrollments`, `course_part_purchases`, `library_purchases`, `wallet_transactions` | Neon | Access, records |
| Watch progress & watch events | Generated by use | `watch_progress`, `watch_events` (start/progress/complete, position, quality, platform) | Neon | Resume, completion, course statistics |
| Notifications & read state, preferences | Generated by use | `notifications`, `notification_preferences` | Neon | Notifications |
| Push token | Optional (only if notifications allowed) | `services/notifications.ts` → `push_tokens` | Neon; delivered via Expo → FCM/APNs | Push delivery |
| Device identifier | Required | `services/device.ts`: SHA-256 of (random keystore secret + Android ID / iOS IDFV + model), computed on device; only the hash is sent (`X-Device-Id`) | `devices.deviceKey` | Device binding, anti-sharing |
| Device name, model, OS version, platform, app version, integrity flag | Required | `X-Device-*` headers | `devices`, `sessions` | Device list, binding, security |
| IP address, user agent | Required (automatic) | `sessions`, `playback_tickets`, `security_events`, `audit_logs` | Neon | Security, fraud prevention |
| Security events (login success/failure, new device, screenshot / recording / external display during protected video, integrity failure) | Required | `services/content-protection.ts` → `POST /playback/security-events`; backend `security_events` | Neon | Content protection, fraud prevention |
| Search queries | Not stored | `modules/search` only reads | — | — |
| Location, contacts, camera, microphone, advertising ID, calendar, SMS, health, files outside the app | **Not collected** | Camera/mic/storage permissions are blocked in `app.config.ts`; no location module | — | — |
| Crash reports / analytics SDK | **None** | No Sentry/Firebase Analytics/etc.; `services/logger.ts` has no remote sink registered | — | — |
| Payment card data | **Not collected** | No card fields in the app; `PAYMENT_PROVIDER` checkout (if ever enabled) is an external page | — | — |

Retention (from code): data kept while the account exists; expired sessions
and refresh tokens deleted 30 days after expiry (`maintenance.processor.ts`).
Account deletion (`users.service.ts softDelete`) disables the account, revokes
sessions/refresh tokens/playback tickets and rewrites the phone to
`deleted:<phone>:<ts>`; all other rows are retained.

Service providers (processors, **not** "sharing" under Play's definition):
Render, Neon, Upstash, Cloudflare (R2 + Worker), Vercel, Expo (push + updates),
Google FCM, Apple APNs.

## 3. App Store Connect → App Privacy

- **Do you or your third-party partners collect data from this app?** Yes
- **Tracking:** No data is used to track. `NSPrivacyTracking: false`, no tracking domains, no ATT prompt needed.

| Identifiers → Device ID | Yes | No | App Functionality |
| Purchases → Purchase History | Yes | No | App Functionality |

The privacy manifest in `app.config.ts` (`ios.privacyManifests`) already
declares the required-reason APIs and no tracking; keep it in sync with this
table.

## 4. Known gap to decide

Deletion keeps name, phone (prefixed), profile photo, device rows and learning
history on the disabled record. Play allows retention for security, fraud
prevention and legal/financial records **when disclosed** — the public pages
disclose it. If you want deletion to also remove the profile photo and device
names and anonymise non-financial data, that is a backend change to
`softDelete` that needs your approval; the pages would then be updated to match.
